# PROJECT_REPORT.md — AquaSense Smart Water Consumption Prediction System

---

## 1. Abstract

AquaSense is an educational machine-learning prototype that predicts daily
household water consumption from eight descriptive household features. A Random
Forest Regressor is trained on a synthetic dataset of 500 households generated
from published per-capita water-use benchmarks. The trained model is served
through a Streamlit web interface that accepts household inputs and returns an
estimated daily water consumption in litres, along with a brief interpretation.
The project demonstrates a complete supervised regression workflow — from data
preparation through model evaluation to interactive deployment — in a simple,
reproducible codebase appropriate for a BCA student demonstration.

---

## 2. Problem Statement and Motivation

Freshwater is a finite and unevenly distributed resource. The United Nations
estimates that by 2025, two-thirds of the world's population could face
water-stressed conditions (UN-Water, 2021). Household water consumption is a
significant and relatively manageable component of total freshwater demand.

Existing awareness tools are typically limited to raw bill data. A predictive
tool that estimates consumption from household characteristics — before a bill
arrives — could help residents, water utilities, and local planners identify
high-use households and prioritise conservation outreach.

This project targets a narrow, well-defined sub-problem: can a regression model
reliably estimate daily household water consumption from easily observable
household features? The answer forms the basis for a working educational
prototype.

## 4. Dataset

### 4.1 Source and Type

The dataset is **synthetic** — generated by `generate_dataset.py` in this
project. It is not real recorded household data.

The generation formulas are based on publicly documented per-activity
water-use benchmarks:

| Reference | Detail |
|-----------|--------|
| Aquastat / FAO | Global per-capita averages (100–200 L/person/day) |
| Ofwat (UK Water Industry) | Household demand components |
| Australian Water Association (AWA) | Per-appliance benchmarks |
| US EPA WaterSense Programme | Fixture and appliance water-use data |

### 4.2 Dataset Properties

| Property          | Value               |
|-------------------|---------------------|
| Rows              | 500                 |
| Features          | 8                   |
| Target variable   | `water_consumption_lpd` |
| Target unit       | Litres per day (L/day) |
| Missing values    | None (by construction) |

### 4.3 Features and Target

| Feature                | Type        | Range         | Unit  |
|------------------------|-------------|---------------|-------|
| `occupants`            | Integer     | 1 – 8         | count |
| `property_size_m2`     | Continuous  | 40 – 210      | m²    |
| `num_bathrooms`        | Integer     | 1 – 4         | count |
| `has_dishwasher`       | Binary      | 0 / 1         | —     |
| `has_washing_machine`  | Binary      | 0 / 1         | —     |
| `avg_temp_celsius`     | Continuous  | 10 – 28       | °C    |
| `garden_size_m2`       | Continuous  | 0 – 65        | m²    |
| `days_away_per_year`   | Integer     | 0 – 100       | days  |
| **`water_consumption_lpd`** | Continuous | 60 – 700 | **L/day (target)** |

### 4.4 Important Disclaimer

Because the dataset is synthetic, model performance figures reflect how well
the model reproduces the generation formulas, not how well it would perform
on real household data. A real-world deployment would require a validated
recorded dataset.

## 6. Methodology and Regression Approach

### 6.1 Algorithm Selection

**Linear Regression** was considered first, as recommended in the project
brief. It was trained as a baseline (see `train_model.py`). However, the
feature set contains:

- Non-linear interactions (e.g. temperature × garden size drives irrigation use).
- Binary flags (dishwasher, washing machine) that interact multiplicatively
  with occupant count.
- Count variables with threshold effects.

**Random Forest Regressor** was selected as the primary model because it:

1. Handles non-linear feature interactions without manual engineering.
2. Works directly with mixed feature types (continuous, integer, binary)
   without scaling.
3. Produces feature importance scores, aiding interpretability.
4. Is well-suited to moderate-sized tabular datasets.

Both models are evaluated and their metrics printed by `train_model.py` so
the performance gain is transparent.

### 6.2 Hyperparameters

| Parameter       | Value | Rationale                             |
|-----------------|-------|---------------------------------------|
| `n_estimators`  | 200   | Stable predictions; low variance      |
| `random_state`  | 42    | Reproducibility                       |
| `n_jobs`        | -1    | Uses all available CPU cores          |

No hyperparameter search was performed; the project scope does not require it.

## 8. Model Evaluation Results

Run `python train_model.py` to obtain the actual metrics for your environment.
Results from a single training run on the 500-row synthetic dataset
(80 % train / 20 % test, `random_state = 42`):

| Metric | Linear Regression (baseline) | Random Forest (selected) |
|--------|------------------------------|--------------------------|
| MAE    | 34.16 L/day                  | **25.21 L/day**          |
| RMSE   | 41.22 L/day                  | **35.04 L/day**          |
| R²     | 0.9601                       | **0.9712**               |

**Interpretation guidance:**

- **MAE** (Mean Absolute Error) — average prediction error in L/day.
  Lower is better.
- **RMSE** (Root Mean Squared Error) — penalises large errors more heavily.
  Lower is better.
- **R²** — proportion of variance in consumption explained by the model.
  A value close to 1.0 is good; a value below 0.5 suggests poor fit.

> **Important:** High R² on synthetic data is expected because the model learns
> the generation formula. These figures do not imply the model would perform
> equally well on real household data.

## 9. Application Features and Limitations

### Features Implemented

- Streamlit web interface with a responsive input form.
- Eight input fields derived from dataset features.
- Input validation with informative error messages.
- Three output metrics: L/day, m³/month, m³/year.
- Contextual interpretation (low / moderate / high / very high).
- Per-person consumption figure in the interpretation text.
- Scatter chart showing occupants vs consumption, coloured by temperature.
- Sidebar with model and dataset information.
- Clear disclaimers at both the page level and below each prediction.

### Limitations

- Trained on synthetic data only.
- Does not capture appliance age, shower duration, regional pricing, or
  seasonal variation beyond average temperature.
- No real-time or IoT data integration.
- No user authentication or persistent storage.
- Not suitable for detecting leaks or forecasting future demand.
- Input range validation is advisory; the model has no hard out-of-range guard.

## 10. Conclusion and Future Improvements

### Conclusion

AquaSense demonstrates that a complete supervised regression pipeline — from
data generation through evaluation to interactive deployment — can be
implemented cleanly in under 400 lines of Python across three files. The
project meets its educational objectives: the workflow is transparent, the
results are honestly reported, and the interface is simple enough for a viva
demonstration.

| Improvement | Feasibility | Notes |
